IMPLEMENTED ROUTES
/tools/error-decoder
- Eight hand-authored rule families: npm ERESOLVE, npm EPERM, PowerShell npm.ps1
  policy errors, Node/Git command lookup, hydration mismatch, module resolution,
  and Vercel build wrappers / NO_OUTPUT_DIRECTORY / FUNCTION_INVOCATION_TIMEOUT.
- Fixed signatures identify symptoms, not proven root causes. A generic build
  exit code without Vercel context does not become a Vercel diagnosis. Multiple
  matches are retained deterministically; unsupported messages get no invented fix.
- Each result includes explanation, possible causes, diagnostics, commands,
  security cautions, evidence/limits, official sources and relevant internal links.
- Input capped at 20,000 characters; terminal formatting/control characters are
  normalized. Text is never rendered as HTML or used as executable code/regex.
- Clipboard actions are explicit, catch permission/API failures, and copy static
  guidance rather than the original visitor log. Commands are never executed.

/tools/package-json-inspector
- Local JSON.parse with malformed/non-object input handling and typed field checks.
- Summaries for dependencies, devDependencies, peerDependencies and optional
  dependencies. Counts reflect declarations, not an installed dependency tree.
- Pattern categories for exact versions, caret/tilde/partial ranges, tags, local
  paths, Git/remote sources, aliases and workspace protocols. Compound ranges are
  not evaluated. Floating/non-registry/unrecognized values receive scoped notes.
- Own version, private, type, packageManager and engines fields receive basic
  checks. Duplicate prod/dev declarations and overrides/workspaces are noted.
- Script text is inert. Common install/prepare hooks, POSIX environment assignment
  and a few deletion/elevation/download-execution patterns prompt review. This is
  neither a complete shell analyzer nor a security verdict. Dependency lifecycle
  hooks not present in the pasted manifest cannot be inspected.
- 100,000-character input cap; up to 200 entries per dependency/engines field,
  80 scripts and 1,000 characters per displayed string. Omissions are disclosed.
- No registry calls, package installation, script execution, lockfile resolution,
  vulnerability scanning, complete schema validation or compatibility guarantee.
  Native JSON parsing keeps the last duplicate key; this limitation is explicit.

PRIVACY / ACCESSIBILITY / DESIGN
Both tools keep input in component memory; analysis adds no transport, storage,
cookie or URL API. Existing site analytics remain and are disclosed. Browsers may
independently restore page state; no memory-erasure guarantee is made. Visitors
are asked to remove secrets. Only a deliberate Copy uses clipboard access, and
the package report warns that displayed private names/script text are included.

The workbench uses existing off-white/charcoal/teal styles with a restrained
editorial header, labelled controls, visible focus, polite status messages,
result-focus scheduling, native forms/details, wrapping controls, responsive
tables and code. Styles are scoped in one CSS module; CMS/admin styling is not
changed. No new runtime or test dependency was introduced.
