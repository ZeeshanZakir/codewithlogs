## Editorial standard

- Start with a specific reader problem and search intent. Explain the symptom, evidence, cause, smallest justified change, and verification.
- Record OS, shell/runtime/framework/dependency versions actually tested. Separate expected results, documentation review, mocks, isolated fixtures and live service tests.
- Use complete readable code where appropriate, security-safe defaults, alternatives, limitations, official references and relevant internal links.
- Never invent personal experience, author credentials, screenshots, benchmarks or successful tests. A plausible example is not verified evidence.
- Keep incomplete or unverified revisions as local drafts. Editorial readiness is distinct from owner publication approval. Draft evidence must never badge a different published body.
- Write natural professional English without filler, keyword stuffing, arbitrary word counts or article-count quotas. Originality review must not claim an external plagiarism check that did not occur.
- Retain useful Next.js, Supabase, deployment and other existing articles. Niche mismatch alone never authorizes archival, merging or redirection.
